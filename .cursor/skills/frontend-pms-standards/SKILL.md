# 前端开发规范（贵港 PMS）

## 执行要求（强制）

1. **开始编码前**：必须先完整阅读并遵循本 SKILL，不得仅凭记忆执行。
2. **演示数据优先**：任何新建/扩展的列表页、TAB 分区、详情页，在提交页面前必须已写入可展示的演示数据；**没有演示数据不得认为页面完成**。
3. **分区等同页面**：列表若按 TAB/大类/类型拆分，**每一个分区都必须单独满足演示数据条款**（禁止只给默认 TAB 造数、其他 TAB 为空或仅 1～2 条且状态不全）。
4. **附件上传统一口径**：凡页面需要上传附件，或用户提到「附件上传」「附件上传栏目」，必须按本技能「附件上传栏目」强制条款实现；附件要求一律来源于**档案配置管理**，禁止在页面内写死一套与档案配置无关的简易上传框。

## 核心原则

1. **技术栈**：必须遵循项目**现有架构** — **React + TypeScript + Vite + react-router-dom + Tailwind CSS**。不得要求迁移至 Vue 或其他框架，不得引入与当前技术栈冲突的 UI 方案（如 Element Plus、Vue SFC 等）。
2. **已有页面保护**：修改现有页面时，**保持当前布局、组件选型与视觉风格**，不得因本规范对已有页面做大规模结构或样式改造。
3. **新建/扩展页面**：优先复用项目内已有布局壳、表格、表单、弹窗、分页等组件与写法，与相邻业务模块保持一致。
4. [reference.md](reference.md) 为历史 EMP/Vue 细则存档，**不适用于本项目，不得执行其中任何条款**。

## 演示数据（强制 · 最高优先级）

适用于：新建演示页、新增列表 TAB/项目大类/业务类型分区、为已有模块补数据。

1. **必须自带可展示数据**：列表、详情、操作历史/审批轨迹（业务需要时）同步生成，写入 `src/mocks/` 或模块既有 mock 文件。
2. **数量与状态**：每个列表（含每个 TAB 分区）建议 **5～10 条**，**必须覆盖该业务全部关键状态**（如草稿/待审/审核中/已通过/已驳回等，以该模块实际状态枚举为准）。
3. **绝对禁止列表为空**：任一 TAB/筛选默认视图不得为空；查询无匹配时回退该分区全量演示数据并中文提示。
4. **分区完整性自检**：若页面有多个 TAB/大类，交付前必须逐个切换确认每个分区有数据且状态齐全；缺数必须先补 mock 再改 UI。
5. **关联数据**：有审批/操作历史的模块，演示记录须能打开轨迹或详情，避免“有列表无详情/无历史”。
6. **缓存失效**：若列表使用 localStorage 缓存演示数据，补充/调整 seed 后须**提升缓存版本号**，确保用户刷新后能加载新数据。

## 附件上传栏目（强制 · 全系统统一 · 说到即生成）

> **触发词**：用户提到「附件上传」「附件上传栏目」「上传附件」，或业务要求页面含附件区时，**一律按本节标准生成**，不得省略栏目标题、标志、模板按钮、提示文案或上传数量提示。
>
> 系统内所有附件上传要求均在**档案配置管理**模块维护。前端凡出现附件上传，必须做成**独立栏目「附件上传」**，按档案配置逐条渲染；界面形态对齐立项/年度计划表单中的附件上传区（见项目内 `AttachmentUploadSection` 实现及本规范案例图）。

### 适用范围

- 新增/编辑表单、详情只读展示、审批/会审/上传弹窗、暂缓/变更等业务表单中，凡需上传或展示附件配置时，一律适用。
- **禁止**：单行「附件」表单项、无配置来源的空白上传按钮、把多种资料混在一个上传区且不展示档案配置字段、只做虚线框不展示名称/必填/存档/模板/提示。

### 栏目级必须项（缺一不可）

1. **栏目标题区**：左侧绿色回形针图标 + 标题文案「附件上传」。
2. **副文案**：标明配置来源，格式：`依据项目档案配置 · {业务节点/模块名} · {大类或类型}`（无大类时可省略末段）。
3. **内容区**：档案配置中的**每一条附件要求**对应一张独立卡片，卡片纵向排列；无配置时中文提示引导至「项目档案配置」维护。

### 每条附件卡片必须展示（与案例图一致）

| 展示项 | 要求 |
|---|---|
| 附件名称 | 档案配置中的资料/文档名称（如「建设工期附件」「论证文件」） |
| 是否必填 | 标签展示「必填」（红底红字）或「选填」（灰底灰字） |
| 是否存档 | 标签展示「存档」（绿底绿字）或「不存档」（灰底） |
| 预览模板 / 下载模板 | 有模板文件时，卡片右上角提供「预览模板」「下载模板」按钮；无模板可不显示 |
| 文件类型与规格 | 一行小字：`文件类型：… · 单文件 ≤ {大小}{单位} · 最多 {N} 个` |
| 提示文案 | 有档案配置备注时，以**浅黄底信息条 + 说明图标**展示提示文案 |
| 附件上传操作 | 虚线框上传区，文案为 `上传文件（还可上传 N 个）`（N 为剩余可传数量）；已传文件可预览/移除；超出大小或数量须中文提示 |

### 视觉与交互要点（对齐案例图）

- 栏目顶栏浅底 + 底部分隔线；卡片白底圆角描边，卡片间距纵向排列。
- 「必填」红标签、「选填」灰标签、「存档」绿标签并排于附件名称右侧。
- 模板按钮靠卡片右上；「下载模板」可用绿色描边强调。
- 规格说明为浅灰小字；提示文案为浅黄条，不得省略有配置备注的提示。
- 上传区为浅灰虚线矩形，居中云上传图标 +「还可上传 N 个」文案，N 随已传数量动态变化。

### 数据与实现约定

1. **配置来源**：读取档案配置相关 mocks/接口（如 `archiveConfigMocks`、业务节点下的附件配置查询方法）；按当前业务节点、项目大类/类型过滤后渲染。
2. **组件复用**：优先复用既有 `AttachmentUploadSection`（或同等结构组件）；新建模块须同一视觉与字段结构，禁止另起简陋上传 UI。
3. **校验**：提交前校验「必填」类附件是否已上传；失败中文提示并滚动定位到附件栏目。
4. **只读场景**：详情/审批查看态仍按同栏目结构展示配置项与已传文件；可不提供上传，但名称、必填/存档、格式与数量说明、提示文案、模板入口应可见。
5. **演示数据**：涉及附件的表单/弹窗，档案配置演示数据须覆盖该业务节点下至少若干附件项（含必填/选填、存档、有备注、有模板），避免空配置栏目。

### 生成后附件栏目自查（说到附件上传时必勾）

- [ ] 已展示独立栏目标题「附件上传」+ 配置来源副文案
- [ ] 每条卡片含：附件名称、必填/选填、存档/不存档
- [ ] 有模板时含：预览模板、下载模板
- [ ] 已展示：文件类型、单文件大小、最多数量
- [ ] 有备注时已展示浅黄提示文案
- [ ] 上传操作区含「还可上传 N 个」
- [ ] 配置来自档案配置，非页面写死简易上传

## 表单 / 详情 / 编辑字段布局（强制 · 新建与改到即执行）

> 目标：新增、编辑、详情字段一目了然，标签列对齐、疏密一致。实现优先复用 `src/components/feature/FormLayout.tsx`（`FormSection` / `FormField` / `FormViewItem` / `FormViewBlock`）。

### 适用范围

- 新增/编辑表单页、详情页、审批/会审弹窗中的**业务字段区**
- 用户明确要求「整洁/对齐/统一表单布局」时，对改到的模块一次性改到位
- **不强制**一次性改造全库历史页面；但**新建表单**或**改到某表单栏目**时必须按本条款执行

### 布局令牌（必须统一）

| 项 | 标准值 |
|---|---|
| 标签列宽 | **130px**（`grid-cols-[130px_1fr]`） |
| 标签样式 | 右对齐、`text-sm text-steel-600`、默认 `whitespace-nowrap` |
| 标签↔控件间距 | `gap-3` |
| 两列短字段外层 | `grid grid-cols-1 md:grid-cols-2 gap-x-8 gap-y-4` |
| 必填标记 | 标签旁红色 `*` |
| 控件 | `px-3 py-2 text-sm`，圆角描边；自动回填用 `readOnly` + `bg-slate-50` |
| 栏目卡片 | 白底圆角描边；顶栏浅底 + 图标 + 标题 + 可选副文案；内容区 `p-5 space-y-4` |

### 排列规则（必须）

1. **短字段**（下拉、日期、数字、人员、编码等）：默认 **两列**，每格均为 `130px + 1fr`。
2. **长单行**（名称、组织选择、长编码）：**整行**占满，不要半空一列。
3. **多行文本 / Textarea**：**始终整行**；标签顶对齐（`items-start`）。
4. **禁止**同一行混用 90/100/110/120/130 等不同标签列宽。
5. **禁止**为挤进三列而把标签缩成 `text-xs`；需要密集展示时仍用两列，或改为表格区。
6. **三列字段网格**原则上不用；确有必要则**同行全部单元格标签列宽仍为 130px**。
7. 详情/只读与编辑使用**同一套标签列宽与网格**；优先 `FormViewItem`（标签左、值右同列），**不要**用「左右两端 justify-between 的 chip 行」展示长业务字段（易错位、难扫读）。
8. 空值统一展示 `—`；长文本 `whitespace-pre-wrap leading-relaxed`。

### 推荐结构（栏目）

```
FormSection（栏目标题）
  └ FormRow2 / FormField（短字段两列）
  └ FormField fullWidth（名称 / 组织 / 多行）
```

详情弹窗业务区：

```
FormViewBlock（区块标题）
  └ FormViewItem × N（两列网格，长字段 fullWidth）
```

### 自查要点

- [ ] 本页（或本弹窗）业务字段标签列宽均为 130px，无混宽
- [ ] 无 `text-xs` 标签凑三列
- [ ] 长文本/名称整行；短字段两列对齐
- [ ] 详情与编辑字段几何一致（或详情使用 FormViewItem）
- [ ] 优先引用 `FormLayout`，避免再复制一套 `labelCls` / `colClass`

## 列表与表单交互（新建页参考 · 不强制改造已有页）

1. 新建列表页时，参考项目中同类列表页的表格、分页与操作列写法；**不要求**统一改造已有列表的固定列、单行展示等实现。
2. 内容较多的新增/编辑/详情，参考项目中同类页面的承载方式（独立路由页或弹窗）；**不要求**将已有弹窗页批量改为独立页或左侧锚点布局。
3. 仅当用户明确要求弹窗或明确要求某种跳转时，按用户要求执行。
4. 校验提示、操作反馈使用中文。
5. **例外**：附件上传不在「不强制改造」豁免范围内——**新建或改到附件相关交互时必须按「附件上传栏目」执行**；用户明确要求整页改造附件区时，须一次性改到位。
6. **例外**：表单字段布局不在「不强制改造」豁免范围内——**新建或改到表单/详情字段区时必须按「表单 / 详情 / 编辑字段布局」执行**。

## 工程组织

- 页面目录：`src/pages/...`，按业务模块分子目录，入口文件沿用项目既有命名（如 `page.tsx`）
- 路由注册：在 `src/router/config.tsx` 中维护
- 国际化：沿用项目现有 `src/i18n` 方案
- 路由、菜单、页面标题与系统名称保持「贵港钢铁工程项目管理系统」口径一致
- 页面文案、注释中禁止出现生成标识文字

## 生成后自查（强制勾选 · 未完成不得收工）

- [ ] 已阅读并遵循本 SKILL
- [ ] 使用 React 现有架构，可本地运行演示
- [ ] **每个列表/每个 TAB 分区**均有演示数据，且覆盖关键业务状态；列表不空
- [ ] 操作历史/审批轨迹已同步（如适用）
- [ ] 若有 localStorage，已升级缓存版本以便新数据生效
- [ ] 与同类已有页面风格一致，未引入无关的大规模 UI 改造
- [ ] 校验与提示为中文
- [ ] 无生成标识类文案
- [ ] **若新建/改到表单或详情字段区**：标签列宽 130px 统一；短字段两列、长文本整行；详情与编辑几何一致；优先使用 `FormLayout`
- [ ] **若说到/含附件上传**：已按「附件上传栏目」生成——栏目标题、附件名称、必填/选填、存档标志、预览/下载模板、文件类型、提示文案、上传操作（含还可上传 N 个）；配置来自档案配置
- [ ] **若说到/含附件上传**：未使用与档案配置脱节的简易单框上传
