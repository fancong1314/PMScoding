# 前端开发规范（贵港 PMS）

## 执行要求（强制）

1. **开始编码前**：必须先完整阅读并遵循本 SKILL，不得仅凭记忆执行。
2. **演示数据优先**：任何新建/扩展的列表页、TAB 分区、详情页，在提交页面前必须已写入可展示的演示数据；**没有演示数据不得认为页面完成**。
3. **分区等同页面**：列表若按 TAB/大类/类型拆分，**每一个分区都必须单独满足演示数据条款**（禁止只给默认 TAB 造数、其他 TAB 为空或仅 1～2 条且状态不全）。
4. **附件上传统一口径**：凡页面需要上传附件，必须按本技能「附件上传栏目」强制条款实现；附件要求一律来源于**档案配置管理**，禁止在页面内写死一套与档案配置无关的简易上传框。

## 核心原则

1. **技术栈**：必须遵循项目**现有架构** — **React + TypeScript + Vite + react-router-dom + Tailwind CSS**。不得要求迁移至 Vue 或其他框架，不得引入与当前技术栈冲突的 UI 方案（如 Element Plus、Vue SFC 等）。
2. **已有页面保护**：修改现有页面时，**保持当前布局、组件选型与视觉风格**，不得因本规范对已有页面做大规模结构或样式改造。
3. **新建/扩展页面**：优先复用项目内已有布局壳、表格、表单、弹窗、分页等组件与写法，与相邻业务模块保持一致。
4. [reference.md](reference.md) 为历史 EMP/Vue 细则存档，**不适用于本项目，不得执行其中任何条款**。

## 演示数据（强制 · 最高优先级）

适用于：新建演示页、新增列表 TAB/项目大类/业务类型分区、为已有模块补数据。

1. **必须自带可展示数据**：列表、详情、操作历史/审批轨迹（业务需要时）同步生成，写入 `src/mocks/` 或模块既有 mock 文件。
2. **数量与状态**：每个列表（含每个 TAB 分区）建议 **5～10 条**，**必须覆盖该业务全部关键状态**（如草稿/待审/审核中/已通过/已驳回等，以该模块实际状态枚举为准）。
3. **绝对禁止列表为空**：任一 TAB/筛选默认视图不得为空；查询无匹配时回退该分区全量演示数据并中文提示。
4. **分区完整性自检**：若页面有多个 TAB/大类，交付前必须逐个切换确认每个分区有数据且状态齐全；缺数必须先补 mock 再改 UI。
5. **关联数据**：有审批/操作历史的模块，演示记录须能打开轨迹或详情，避免“有列表无详情/无历史”。
6. **缓存失效**：若列表使用 localStorage 缓存演示数据，补充/调整 seed 后须**提升缓存版本号**，确保用户刷新后能加载新数据。

## 附件上传栏目（强制 · 全系统统一）

> 系统内所有附件上传要求均在**档案配置管理**模块维护。前端凡出现附件上传，必须做成**独立栏目「附件上传」**，按档案配置逐条渲染，界面形态对齐年度计划申报表单中的附件上传区（见项目内 `AttachmentUploadSection` 实现）。

### 适用范围

- 新增/编辑表单、详情只读展示、审批/会审弹窗、暂缓/变更等业务表单中，凡需上传或展示附件配置时，一律适用。
- **禁止**：单行「附件」表单项、无配置来源的空白上传按钮、把多种资料混在一个上传区且不展示档案配置字段。

### 栏目结构（必须）

1. **独立栏目容器**：单独一块「附件上传」分区（有栏目标题区 + 内容区），不得拆散到其他字段行内。
2. **栏目标题**：图标 + 文案「附件上传」；副文案标明配置来源，格式示例：`依据项目档案配置 · {业务节点/模块名} · {大类或类型}`。
3. **按配置逐条卡片**：档案配置中的**每一条附件要求**对应一张横向卡片，卡片之间纵向排列；无配置时中文提示引导至档案配置维护。

### 每条附件卡片必须展示的信息

| 展示项 | 要求 |
|---|---|
| 附件名称 | 档案配置中的资料/文档名称（如「项目建议书」「可行性研究报告」） |
| 是否必填 | 标签展示「必填」或「选填」 |
| 是否存档 | 标签展示「存档」或「不存档」 |
| 查看/下载模板 | 有模板文件时提供「预览模板」「下载模板」按钮；无模板可不显示按钮 |
| 附件上传备注 | 有备注时以醒目提示条展示（黄底信息条 + 说明图标） |
| 文件类型与格式 | 展示允许的文件类型，如 PDF、Word(doc/docx)、Excel(xls/xlsx)、图片(jpg/png/bmp) 等 |
| 单文件大小限制 | 如「单文件 ≤ 100MB」 |
| 上传数量限制 | 如「最多 10 个」；上传区文案体现剩余可传数量 |
| 上传操作区 | 虚线框上传入口；已上传文件列表可移除；超出大小/数量须中文提示 |

### 数据与实现约定

1. **配置来源**：优先读取档案配置相关 mocks/接口（如 `archiveConfigMocks`、业务节点下的附件配置查询方法）；按当前业务节点、项目大类/类型过滤后渲染。
2. **组件复用**：能复用则复用既有 `AttachmentUploadSection`（或同等结构组件）；新建模块时按同一视觉与字段结构实现，禁止另起一套简陋上传 UI。
3. **校验**：提交前校验「必填」类附件是否已上传；校验失败中文提示并定位到附件栏目。
4. **只读场景**：详情/审批查看态仍按同栏目结构展示配置项与已传文件；可不提供上传，但名称、必填/存档、格式与数量说明、备注、模板入口应可见（按业务需要）。
5. **演示数据**：涉及附件的表单页，档案配置演示数据须覆盖该业务节点下至少若干附件项（含必填/选填、存档/不存档、有备注、有模板），避免空配置栏目。

### 视觉参考要点（对齐案例图）

- 栏目顶栏浅底分隔；卡片白底圆角描边。
- 「必填」红标签、「存档」绿标签；备注用浅黄提示条。
- 规格说明一行小字：文件类型 · 单文件大小 · 最多数量。
- 底部虚线上传区：`上传文件（还可上传 N 个）`。

## 列表与表单交互（新建页参考 · 不强制改造已有页）

1. 新建列表页时，参考项目中同类列表页的表格、分页与操作列写法；**不要求**统一改造已有列表的固定列、单行展示等实现。
2. 内容较多的新增/编辑/详情，参考项目中同类页面的承载方式（独立路由页或弹窗）；**不要求**将已有弹窗页批量改为独立页或左侧锚点布局。
3. 仅当用户明确要求弹窗或明确要求某种跳转时，按用户要求执行。
4. 校验提示、操作反馈使用中文。
5. **例外**：附件上传不在「不强制改造」豁免范围内——**新建或改到附件相关交互时必须按「附件上传栏目」执行**；用户明确要求整页改造附件区时，须一次性改到位。

## 工程组织

- 页面目录：`src/pages/...`，按业务模块分子目录，入口文件沿用项目既有命名（如 `page.tsx`）
- 路由注册：在 `src/router/config.tsx` 中维护
- 国际化：沿用项目现有 `src/i18n` 方案
- 路由、菜单、页面标题与系统名称保持「贵港钢铁工程项目管理系统」口径一致
- 页面文案、注释中禁止出现生成标识文字
